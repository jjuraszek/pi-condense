# Contributing

## Issues

File via the issue templates - every ticket is Context / Problem / Idea / Acceptance Criteria. Bugs need repro steps, observed-vs-expected behavior, and versions.

On intake the maintainer may restructure title and body with the pi-gauntlet `shape-ticket` skill (AC integrity gate, council roast). Intent, links, and attachments are preserved; acceptance criteria may be sharpened, the ticket parked with the blocker named, or a split proposed for your approval.

## Pull requests

PRs land through the maintainer's pi-gauntlet workflow (spec -> plan -> subagent review); yours may be re-scoped or rewritten in the process. Simple one-liner fixes skip the ceremony.

The bar applies to every PR, one-liners included: a PR is rejected when code and documentation drift apart. If behavior, config, or commands change, README / docs / CHANGELOG change in the same PR.
